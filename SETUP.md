# Налаштування з нуля

Терміналу не буде. Тільки браузер. Приблизно 30 хвилин.

---

## Крок 1. Акаунт GitHub

Відкрийте **github.com** → Sign up. Пошта, пароль, ім'я користувача. Безкоштовного тарифу вистачає з запасом.

---

## Крок 2. Створити репозиторій

1. Праворуч угорі **+** → **New repository**
2. Repository name: `news-brief`
3. Виберіть **Public**
   Це важливо: Claude має читати ваш дайджест за прямим посиланням, а приватний репозиторій він відкрити не зможе. Усередині будуть лише заголовки новин — нічого особистого.
4. Поставте галочку **Add a README file**
5. **Create repository**

---

## Крок 3. Завантажити файли

На сторінці репозиторію: **Add file** → **Upload files**.

Перетягніть **усі файли з архіву**, зберігши структуру папок. Браузер приймає перетягування цілих папок — просто киньте вміст архіву в вікно.

Має вийти така структура:

```
news-brief/
├── .github/workflows/brief.yml
├── .github/workflows/discover.yml
├── scripts/collect.py
├── scripts/discover.py
├── sources.csv
├── requirements.txt
├── digests/.gitkeep
└── state/.gitkeep
```

Унизу натисніть **Commit changes**.

> Якщо папка `.github` не завантажилась (браузери іноді ховають папки з крапкою на початку):
> **Add file** → **Create new file** → у полі імені введіть `.github/workflows/brief.yml`
> — GitHub сам створить папки. Вставте вміст файлу, збережіть. Повторіть для `discover.yml`.

---

## Крок 4. Дозволити запис

**Settings** (вкладка репозиторію) → у лівому меню **Actions** → **General** →
прокрутіть до **Workflow permissions** → виберіть **Read and write permissions** → **Save**.

Без цього робот не зможе зберігати дайджести.

---

## Крок 5. Перевірити стрічки

Вкладка **Actions** → зліва **Перевірити стрічки** → кнопка **Run workflow** → **Run workflow**.

Займе 3–6 хвилин. Коли з'явиться зелена галочка, у репозиторії будуть два нових файли:

- **`feed-report.md`** — відкрийте його. Це і є ваша відповідь про помилки: скільки стрічок живі, які не відповіли і чому.
- **`feeds.json`** — робочий список, з яким далі працює збірник.

Надішліть мені `feed-report.md`, і я підберу заміну всім, що не відповіли.

---

## Крок 6. Перший дайджест

**Actions** → **Щоденний дайджест** → **Run workflow**.

Через кілька хвилин у папці `digests/` з'явиться файл з сьогоднішньою датою. Далі це відбуватиметься саме, щодня о 07:00.

---

## Крок 7. Ключ до API

Це те, чим оплачується написання брифу. Приблизно $5–8 на місяць.

1. Відкрийте **console.anthropic.com**, увійдіть тією ж поштою, що й Claude
2. **Billing** → поповніть баланс на мінімальну суму. Це окремий рахунок від підписки
3. **API keys** → **Create key** → скопіюйте ключ

Ключ показується **один раз**. Не закривайте вкладку, поки не вставите його в кроці 9.

> Порада: у **Billing → Limits** одразу поставте місячний ліміт, скажімо $15. Якщо щось піде не так, більше цього не спишеться.

---

## Крок 8. Telegram-бот

1. У Telegram знайдіть **@BotFather**, натисніть Start
2. Надішліть `/newbot`. Він спитає назву й ім'я користувача бота (має закінчуватись на `bot`, наприклад `moi_brief_bot`)
3. У відповідь прийде **токен** виду `8123456789:AAF...` — скопіюйте
4. Знайдіть свого бота в пошуку, відкрийте, натисніть **Start** і напишіть йому будь-що. Без цього бот не має права вам писати
5. Відкрийте в браузері, підставивши свій токен:
   ```
   https://api.telegram.org/botТОКЕН/getUpdates
   ```
   Знайдіть у тексті `"chat":{"id":123456789` — оце число і є ваш **chat id**

---

## Крок 9. Скласти секрети в репозиторій

**Settings** → у лівому меню **Secrets and variables** → **Actions** → **New repository secret**.

Створіть три штуки, по одній:

| Name | Secret |
|---|---|
| `ANTHROPIC_API_KEY` | ключ із кроку 7 |
| `TELEGRAM_BOT_TOKEN` | токен із кроку 8 |
| `TELEGRAM_CHAT_ID` | число з кроку 8 |

Імена мають збігатися посимвольно. Секрети після збереження не показуються — це нормально, їх читає тільки робот.

---

## Крок 10. Перший бріф

**Actions** → **Ранковий бріф** → **Run workflow**.

Через 5–8 хвилин бріф має прийти в Telegram. Далі це відбуватиметься саме, щодня о 07:00.

---

## Що буде далі щодня

| Час | Що відбувається | Ціна |
|---|---|---|
| 07:00 | GitHub тягне 252 стрічки, чистить, групує, стискає | безкоштовно |
| 07:03 | Дайджест іде в API, повертається готовий бріф | ~20 центів |
| 07:04 | Бріф приходить у Telegram | безкоштовно |

---

## Якщо щось зламалось

**Червоний хрестик у Actions.** Натисніть на запуск → на крок з хрестиком → там текст помилки. Скопіюйте мені.

**Дайджест не оновлюється.** GitHub вимикає розклад у репозиторіях, де 60 днів не було активності. Він надішле листа. Досить зайти в Actions і натиснути Run workflow — розклад відновиться.

**Стрічка перестала відповідати.** Вона автоматично пропускається, а її назва потрапляє в рядок «Не відповіли» на початку дайджесту. Якщо та сама назва там третій день — надішліть мені, підберу заміну.

**Розклад збився на годину.** Зимовий/літній час. У файлі `.github/workflows/brief.yml` змініть `'0 4 * * *'` на `'0 5 * * *'` (взимку) і навпаки.

---

## Як правити бріф пізніше

Формат випуску живе у файлі **`prompts/brief.md`**, окремо від коду. Хочете інші країни в ядрі, довші блоки, інший тон — відкриваєте цей файл прямо на GitHub, натискаєте олівець, правите текст, **Commit changes**. Наступний ранок вийде вже за новими правилами.

Список видань — у **`sources.csv`**, так само редагується в браузері. Після зміни прожене **Перевірити стрічки**, щоб нові адреси знайшлись.

---

## Скільки це коштує насправді

Перший тиждень подивіться на рядок у логах кроку «Написати бріф» — там друкується точна кількість токенів за запуск. Помножте на 30 і звірте з рахунком у консолі. Мої $5–8 — оцінка, а не обіцянка: реальна цифра залежить від того, скільки новин у світі того дня.

## Крок 11. Токен Telegraph

Повний випуск публікується на telegra.ph, а в Telegram приходить коротка
верхівка з посиланням.

Токен треба створити **вручну один раз** і покласти в Secrets. Автоматично
його створювати не можна: тоді він лежав би у файлі публічного репозиторію,
і будь-хто зміг би публікувати й редагувати сторінки від вашого імені.

1. Відкрийте в браузері:
   ```
   https://api.telegra.ph/createAccount?short_name=brief&author_name=Ранковий%20бріф
   ```
2. У відповіді знайдіть `access_token` — довгий рядок символів. Скопіюйте його.
3. **Settings → Secrets and variables → Actions → New repository secret**
   Name: `TELEGRAPH_TOKEN`, Secret: скопійований токен.

Токен показується лише в цій відповіді браузера. Якщо загубили — просто
відкрийте посилання ще раз і отримайте новий; старі сторінки лишаться на місці,
але редагувати їх старим акаунтом ви вже не зможете.

**Якщо секрету немає**, пайплайн не зламається: крок публікації тихо
пропуститься, а випуск прийде в Telegram повністю, кількома повідомленнями.

**Якщо токен колись скомпрометують** — створіть новий за тим самим посиланням
і замініть секрет. Опубліковані сторінки лишаться доступними за старими
адресами, але чужий токен більше нічого не редагуватиме.
